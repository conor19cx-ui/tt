# 本周Redis学习小结

本周我围绕Redis的基础应用与项目实践展开学习，结合短信验证码功能开发、点赞功能扩展，逐步掌握Redis的核心用法、数据类型选择及实际开发中的避坑技巧，现将学习内容与收获总结如下，贴合本周学习轨迹，重点梳理实操中的重点与难点。

## 一、本周核心学习内容

### （一）Redis基础认知与环境操作

1.  掌握Redis的基础特性：了解Redis是基于内存的高性能键值对数据库，支持多种数据类型，操作高效，适合作为缓存使用；

2.  环境操作：学会使用Another Redis Desktop Manager可视化工具连接本地Redis（127.0.0.1:6379，DB0），进行Key的查看、刷新、删除等操作；同时掌握Redis命令行操作，通过redis-cli连接Redis，使用SET、GET、KEYS、SCARD等命令直接操作数据，排查问题更高效。

### （二）Redis核心数据类型实践（重点）

本周结合项目实践，重点掌握了两种最常用的Redis数据类型，明确不同场景下的选型逻辑，这也是老师课堂重点强调的内容：

1.  String类型（核心应用：短信验证码）

- 适用场景：存储简单文本、数字，适合短信验证码这类短内容、需快速读写的场景；

- 实操应用：将6位随机验证码以String类型存入Redis，设置300秒（5分钟）过期时间，通过SET命令写入、GET命令读取，校验成功后用DELETE命令删除，保证验证码一次性、限时有效；

- 关键要点：明确String类型的核心操作，理解TTL过期时间的作用，避免验证码永久存储带来的安全风险。

2.  Set类型（核心应用：点赞功能）

- 适用场景：存储不重复的集合数据，适合需要去重、判断元素是否存在、统计数量的场景（如点赞）；

- 实操应用：设计Key格式为“like:article:文章ID”，将点赞用户ID存入Set集合，通过SADD（点赞）、SREM（取消点赞）、SISMEMBER（判断是否已点赞）、SCARD（统计点赞数）命令实现点赞功能；

- 关键要点：利用Set自动去重的特性，避免同一用户重复点赞，充分发挥Redis高性能的优势。

### （三）项目实践：Redis结合Spring Boot开发

本周核心实践是基于Spring Boot整合Redis，开发两个核心功能，完成从代码搭建到接口测试的全流程：

1.  短信验证码功能（已完成）

- 核心流程：接收手机号→校验格式→生成6位验证码→存入Redis（String类型，设置TTL）→提供发送、校验两个接口，校验成功后删除Redis中的验证码；

- 核心接口：发送验证码（POST /api/sms/verify-codes）、校验验证码（POST /api/sms/verify-codes/validate）；

- 技术实现：封装RedisUtil工具类，简化Redis的set、get、delete操作；使用Spring Validation进行参数校验（手机号格式、非空校验）；统一接口响应格式，保证接口规范。

2.  点赞功能（新增扩展）

- 核心逻辑：基于Set类型实现点赞、取消点赞、点赞状态判断、点赞数统计，Key命名遵循“业务前缀:模块:标识”的规范，避免Key冲突；

- 核心优势：无数据库依赖，纯Redis缓存架构，操作高效，适合高并发场景，天然解决重复点赞问题。

### （四）常见问题与避坑经验（本周重点解决的问题）

本周在实操过程中遇到多个问题，通过排查逐步掌握避坑技巧，也是学习中的重要收获：

- 接口400错误：原因是JSON请求体包含注释（标准JSON不支持注释）、手机号格式错误（非11位数字），解决方法是删除注释，保证手机号为11位有效数字，JSON格式为纯键值对；

- Redis中看不到Key：原因是Redis配置错误（地址、端口、数据库选错）、Key已过期或校验成功后被删除，解决方法是确认Redis连接配置正确，发送验证码后及时刷新Redis查看；

- RedisUtil注入失败：原因是工具类未添加@Component注解，导致Spring无法扫描管理，解决方法是给RedisUtil添加@Component注解，确保包路径正确；

- Redis重启后数据丢失：原因是Redis默认将数据存储在内存中，未开启持久化，了解到这是正常现象，作业场景无需开启持久化，核心功能不受影响。

## 二、学习收获与重点掌握

1. 掌握Redis两种核心数据类型（String、Set）的选型逻辑和实操命令，明确不同业务场景下的合理选型（验证码用String，点赞用Set）；

2. 学会Spring Boot整合Redis的基本方法，能独立封装Redis工具类，开发基于Redis的业务接口；

3. 理解Redis Key的命名规范，能设计清晰、无冲突的Key，方便后续管理和排查；

4. 掌握接口测试方法（使用Apifox），能独立完成接口的调用、调试，排查接口报错和Redis操作相关问题；

5. 理解短信验证码的安全规范（限时、一次性），掌握点赞功能的核心逻辑（去重、统计），贴合企业开发规范。
